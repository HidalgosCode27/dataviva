Stock reconciliation

Match the stock the client sees with the stock in the WMS. A SQL FULL OUTER JOIN, and the same match in pandas, so rows that live on only one side are not dropped.

  • SQL
  • PostgreSQL

Context

On the logistics operation I’m supporting, two lists describe the same stock: the client’s system and the WMS. The case is reconciling them. I don’t name commercial systems, clients, or people.

Problem

An INNER JOIN drops the SKU that exists on only one side. That is exactly the gap a reconciliation has to show: units that don’t match, and references missing from one of the two systems.

What I did

I proposed the match as a FULL OUTER JOIN, and the pandas equivalent (merge with how="outer"). In the example, the difference is client units minus WMS units. If one side has no SKU, it counts as zero only for that subtraction.

Example data. Invented SKUs and units. This is not stock from a client or a WMS.

reconcile.sqlExample data
-- Example data. This is not a real schema.
WITH client AS (
  SELECT * FROM (VALUES
    ('SKU-101', 120),
    ('SKU-204', 40),
    ('SKU-318', 15)
  ) AS t(sku, units)
),
wms AS (
  SELECT * FROM (VALUES
    ('SKU-101', 118),
    ('SKU-204', 40),
    ('SKU-422', 7)
  ) AS t(sku, units)
)
SELECT
  COALESCE(c.sku, w.sku) AS sku,
  c.units AS client_units,
  w.units AS wms_units,
  COALESCE(c.units, 0) - COALESCE(w.units, 0) AS difference
FROM client AS c
FULL OUTER JOIN wms AS w ON c.sku = w.sku
ORDER BY sku;
reconcile.pyExample data
import pandas as pd

client = pd.DataFrame({
    "sku": ["SKU-101", "SKU-204", "SKU-318"],
    "units": [120, 40, 15],
})
wms = pd.DataFrame({
    "sku": ["SKU-101", "SKU-204", "SKU-422"],
    "units": [118, 40, 7],
})

matched = client.merge(wms, on="sku", how="outer", suffixes=("_client", "_wms"))
matched["difference"] = matched["units_client"].fillna(0) - matched["units_wms"].fillna(0)
An illustrative result of that query, using the same fake data. A positive difference means more units in the client’s system; a negative one means more in the WMS.
SKU Client WMS Difference
SKU-101 120 118 2
SKU-204 40 40 0
SKU-318 15 — 15
SKU-422 — 7 −7

SKU-318 is only on the client side. SKU-422 is only in the WMS. An inner join would have dropped both from the list.
