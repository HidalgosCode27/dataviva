Shift-lead form

A shift report in Streamlit, saved to SQLite. The architecture is three modules: app.py, validar.py, and storage.py.

  • Python
  • Streamlit
  • SQLite

Context

On the logistics operation, each shift lead files a report. The form puts that note into fields instead of a loose message. I don’t use real names: in the examples the lead is “Example lead”.

Problem

A repeated report dirties the history. The duplicate rule is specific: same date, same shift lead, and same shift.

[To do: what failed in the previous process]

What I did

I split the app into three pieces. The screen does not decide on its own whether a report is new: it asks the validation module and, if it passes, hands it to storage.

  1. app.py The Streamlit form: date, shift lead, shift, and note.
  2. validar.py The rules. A row is a duplicate when date, lead, and shift all match.
  3. storage.py Reads and writes the report in SQLite.

Example data. The mock does not submit anything, and the snippets are not the real source: they illustrate the architecture.

app.pyExample data
import streamlit as st
from validar import is_duplicate
from storage import save, load

st.title("Shift report")

report = {
    "date": str(st.date_input("Date")),
    "lead": st.text_input("Shift lead"),
    "shift": st.selectbox("Shift", ["Morning", "Afternoon", "Night"]),
    "note": st.text_area("Note"),
}

if st.button("Save"):
    if is_duplicate(report, load()):
        st.error("A report already exists for that date, lead, and shift.")
    else:
        save(report)
        st.success("Report saved.")
validar.pyExample data
KEY = ("date", "lead", "shift")

def is_duplicate(report, existing):
    key = tuple(report[field] for field in KEY)
    for previous in existing:
        if tuple(previous[field] for field in KEY) == key:
            return True
    return False
storage.pyExample data
import sqlite3

def save(report):
    with sqlite3.connect("reports.db") as con:
        con.execute(
            """
            INSERT INTO reports (date, lead, shift, note)
            VALUES (:date, :lead, :shift, :note)
            """,
            report,
        )

If another report comes in for 2024-03-12, lead “Example lead”, and the Morning shift, is_duplicate returns true and it is not saved. Change the date, the lead, or the shift, and it is no longer the same report.
